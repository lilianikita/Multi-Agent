# Инструкция: Автоматизированный QA-анализ и проектирование

Этот проект использует AI-агентов на базе OpenCode для полной автоматизации процесса превращения требований в задачи для разработки и тестовую документацию.

---

## Архитектура процесса

При выполнении команды запускается цепочка из четырёх специализированных агентов:

1. **requirement-review** — Анализирует страницу в Confluence, выделяет бизнес-правила и риски.
2. **jira-task** — Проектирует задачи в Jira на основе утверждённого анализа.
3. **test-model** — Создаёт тестовую модель в Testomat.io.
4. **qa-orchestrator** — Контролирует Quality Gates, связывает артефакты и формирует финальный отчёт.

---

## Предварительные условия

Перед запуском убедитесь, что:

- Установлен и обновлён **opencode**.
- В конфигурации `opencode.json` подключены MCP-серверы для **Confluence**, **Jira** и **Testomat.io**.
- В конфигурации прописаны навыки (Skills) или агенты: `requirement-review`, `task-design`, `test-design`.
- Учётная запись, от имени которой работает OpenCode, имеет права на чтение в Confluence и права на создание задач/тестов в Jira и Testomat.io.
- В проекте создан каталог `artifacts/` для сохранения результатов.

---

## Как запустить

Откройте терминал в корне вашего проекта и выполните команду:

```bash
opencode "выполни анализ требований страницы Confluence [PAGE_ID], создай задачи в Jira и тестовую модель в Testomat.io"
```

Замените `[PAGE_ID]` на числовой идентификатор страницы в Confluence (его можно найти в URL страницы).

### Пример

```bash
opencode "выполни анализ требований страницы Confluence 123456, создай задачи в Jira и тестовую модель в Testomat.io"
```

---

## Что произойдёт после запуска

1. **Анализ (requirement-review):** Агент заберёт текст из Confluence, разберёт его на правила и ограничения. Если в требованиях есть противоречия, процесс остановится на этом этапе и потребует вашего вмешательства.
2. **Проектирование (jira-task & test-model):** Если требования валидны, агенты создадут задачи в Jira (с привязкой к Confluence) и тест-кейсы в Testomat.io (с привязкой к требованиям).
3. **Контроль (qa-orchestrator):** Агент проверит, что все артефакты созданы физически (проверит ID), свяжет их в карту соответствия (Traceability Matrix) и сохранит отчёт.

---

## Где искать результаты

Все промежуточные и финальные результаты сохраняются в каталоге `artifacts/` вашего проекта. Структура будет следующей:

```
artifacts/
├── requirements-review/
│   └── v1.md                  # Структурированный разбор требований
├── jira-tasks/
│   └── v1.md                  # Список созданных задач и их ID
├── test-cases/
│   └── v1.md                  # Список созданных тестов и их ID
├── traceability/
│   ├── tasks-v1.md            # Матрица: Требование → Jira
│   └── tests-v1.md            # Матрица: Требование → Testomat
└── final-report/
    └── v1.md                  # Итоговый отчёт о прохождении Quality Gates
```

> **Важно:** При каждом повторном запуске старые версии артефактов не удаляются. Номер версии (v1, v2, …) будет увеличиваться.

---

## Правила остановки (Quality Gates)

Процесс может прерваться, если сработают автоматические проверки:

- **Data Error:** Требования в Confluence противоречат друг другу.
- **Missing Info:** В тексте не хватает данных для создания задачи (например, не указано, что делать при ошибке).
- **Technical Error:** Jira или Testomat недоступны после 3 попыток обращения.

В этом случае `qa-orchestrator` сохранит всё, что успел сделать, и в файле `artifacts/final-report/v1.md` будет чётко указано, на каком этапе произошла остановка и почему.

---

## Правила эскалации (когда обращаться к человеку)

Агент остановится и задаст вопрос, если:

- Выявлено прямое противоречие в требованиях (например, «кнопка должна быть красной» и «кнопка должна быть зелёной»).
- Отсутствует критически важная бизнес-логика.
- Системы Jira/Testomat вернули ошибку прав доступа.

В этом случае проверьте файл `artifacts/final-report/v1.md` и задайте уточняющий вопрос в чате с OpenCode.

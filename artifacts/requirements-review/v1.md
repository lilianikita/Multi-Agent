# Анализ требований — v1

**Источник:** Confluence pageId=2129921 — «Требования ДЗ Лекция 10 #2»
**Дата анализа:** 2026-10-29

---

## Синтез (суть требований)

Необходимо разработать интернет-магазин продуктов питания с полным циклом: регистрация/авторизация пользователей, каталог товаров с поиском и фильтрацией, корзина, оформление заказа с выбором адреса/времени/оплаты, отслеживание доставки и административная панель для управления товарами, заказами, курьерами и аналитикой.

## 2. Бизнес-правила

| ID | Правило | Источник |
|----|---------|----------|
| BR-01 | Если пользователь ввёл неверный пароль 5 раз подряд, то доступ к аккаунту блокируется на 15 минут | FR-04 |
| BR-02 | Если сумма заказа меньше минимальной (1000 руб.), то переход к оформлению блокируется | FR-28 |
| BR-03 | Если товар отсутствует на складе, система предлагает 2-3 аналогичных товара и опцию «Разрешать замену» | FR-29 |
| BR-04 | Если пользователь покупает алкоголь, система проверяет дату рождения | FR-08 |
| BR-05 | При оформлении заказа остаток товара на складе автоматически резервируется | FR-46 |

## 3. Ограничения

| ID | Ограничение |
|----|-------------|
| C-01 | Подсказки в поиске появляются только после ввода первых трёх букв |
| C-02 | Минимальная сумма заказа — 1000 рублей (значение может меняться для разных адресов) |
| C-03 | Интервал доставки — двухчасовой |

## 4. Критерии приемки (Acceptance Criteria)

Каждый функциональный FR имеет соответствующий критерий: система реализует описанную функцию. Дополнительно выделены:

| ID | Критерий | Связанное FR |
|----|----------|--------------|
| AC-01 | Пользователь может зарегистрироваться по номеру телефона, получить SMS-код и подтвердить аккаунт | FR-01 |
| AC-02 | Пользователь может зарегистрироваться по email и подтвердить аккаунт | FR-02 |
| AC-03 | После 5 неудачных попыток входа система блокирует доступ на 15 минут с соответствующим сообщением | FR-04 |
| AC-04 | Пользователь может сбросить пароль через SMS и через email | FR-05, FR-06 |
| AC-05 | Пользователь может просматривать/редактировать профиль, видеть историю заказов, повторять заказы | FR-07, FR-09 |
| AC-06 | Пользователь может сохранять несколько адресов и назначать адрес по умолчанию | FR-10 |
| AC-07 | При сумме заказа менее 1000 руб. пользователь видит предупреждение и не может оформить заказ | FR-28 |
| AC-08 | Поиск отображает подсказки после ввода 3+ символов и исправляет опечатки | FR-18, FR-19 |
| AC-09 | При отсутствии товара пользователю предлагаются аналоги (2-3 шт.) | FR-29 |
| AC-10 | После оплаты заказ переходит в соответствующий статус, пользователь получает уведомления | FR-38, FR-40, FR-41 |
| AC-11 | Администратор может управлять товарами, заказами, курьерами, пользователями и видеть аналитику | FR-43–FR-52 |

## 5. Связи и зависимости

| Зависимость | Описание |
|-------------|----------|
| FR-03 → FR-01, FR-02 | Авторизация возможна только после реализации регистрации |
| FR-31 → FR-10 | Выбор адреса при оформлении зависит от сохранённых адресов |
| FR-28 → FR-25, FR-26, FR-27 | Проверка минимальной суммы зависит от функционала корзины |
| FR-37 → FR-31, FR-32, FR-33, FR-34, FR-35, FR-36 | Экран подтверждения зависит от всех шагов оформления |
| FR-47 → FR-46 | Управление заказами в админке зависит от резервирования остатков |

## 8. Пробелы (Missing Information)

| ID | Описание |
|----|----------|
| MI-01 | Не описаны роли пользователей в админ-панели (кто может управлять товарами, кто — только заказами) |
| MI-02 | Не описан процесс отказа/возврата товара |
| MI-03 | Не указано поведение системы при недоступности SMS-шлюза или email-сервера |
| MI-04 | Не указаны сценарии ошибок при оплате (недостаточно средств, отказ банка) |
| MI-05 | Не описана обработка случая, когда все курьеры заняты |
| MI-06 | Не указана максимальная длина комментария к заказу |

## 9. Риски (Risks)

| ID | Описание |
|----|----------|
| R-01 | Обработка опечаток в поиске требует интеграции с сервисом исправления опечаток (например, Яндекс.Спеллер) или собственного словаря |
| R-02 | Отслеживание курьера в реальном времени требует интеграции с картографическим сервисом (карта, геолокация) |
| R-03 | SMS-подтверждение при регистрации и восстановлении зависит от внешнего SMS-провайдера |
| R-04 | Автоматическое резервирование остатков требует транзакционной целостности БД |
| R-05 | Определение зоны доставки по адресу требует геокодинга |

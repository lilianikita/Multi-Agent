## 3. Формат шагов

Все кейсы описаны в Given-When-Then, шаги атомарные, данные — плейсхолдеры (`{phone}`, `{sms_code}`, `{promo_code}`, `{min_order_sum}` и т.д.), без «магических» значений.

Пример (`f9dc374e`):

```
**Given** Выбран адрес {address} с минимальной суммой {min_order_sum}
**And** Сумма корзины {cart_sum} меньше {min_order_sum}
**When** Пользователь пытается перейти к оформлению
**Then** Отображается предупреждение о минимальной сумме
**And** Переход к оформлению заблокирован
```

## 5. Что не покрыто (осознанно)

- UI-проверки (вёрстка, адаптив, визуальные элементы) — вне Scope навыка `test-design`.
- Технические/интеграционные проверки (SMS-провайдер, платёжный шлюз, картография) — в требованиях нет критериев.
- Возрастная проверка 18+ — порог и правила отсутствуют в источнике (MISS-01), кейс не создавался, чтобы не выдумывать правило.
- Отмена заказа и возврат средств — не описаны в источнике (MISS-04).
